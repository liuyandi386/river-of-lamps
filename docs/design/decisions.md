## `max_components` 到底是什么？

可以把它理解成：

> **这一关最多允许你放几个“有功能的零件”。**

- **算**：与门、或门、非门、延迟元件、脉冲发生器、计数器、中继器……这些“会处理信号”的东西。
- **不算**：灯槽（导线）。灯槽是“路”，不是“零件”；如果灯槽也算，8×8 网格上一条长路就先把预算吃光了。

举例：

- 一关写 `"max_components": 3`，意思是玩家最多放 3 个功能元件。
- 玩家放了 2 个与门 + 1 个非门 = 3 个，刚好。
- 中间铺了 12 格灯槽，不增加这 3 的计数。

**MVP 现状**：5 关里的门都是预置的，玩家只画灯槽，所以计数是 `0 / 10`。这个上限主要是给后面“元件数量上限”关卡用的，现在先把规则定清楚，避免以后返工。

> 如果以后想让“灯槽也受限”，可以再加一个独立的 `max_wire_cells`，不要和 `max_components` 混在一起。

## C17 的参数是什么意思？

这些是“时间旋钮”。MVP 只用到信号源，但先把规则定好，第二批直接接上。

### 信号源（source）

| 参数 | 含义 | 默认 |
|---|---|---|
| `mode` | `high` 持续高 / `low` 持续低 / `pulse` 只亮一下 | `high` |
| `pulse_at_tick` | `pulse` 模式在第几拍亮 | `0`（第 0 拍） |

例：`"mode": "pulse", "pulse_at_tick": 0` → 第 0 拍亮，第 1 拍就灭。

### 脉冲发生器（pulse，第二批）

| 参数 | 含义 | 默认 |
|---|---|---|
| `period` | 每几拍重复一次 | `4` |
| `high_ticks` | 每次亮几拍 | `1` |
| `phase` | 从第几拍开始算 | `0` |

例：`period=4, high_ticks=1` → 第 0、4、8… 拍亮。

### 边沿触发器（edge_trigger，第二批）

| 参数 | 含义 | 默认 |
|---|---|---|
| `edge` | `rising` 上升沿 / `falling` 下降沿 | `rising` |
| `initial` | 初始输出 | `0` |

### 计数器（counter，第二批）

| 参数 | 含义 | 默认 |
|---|---|---|
| `n` | 每 N 个脉冲输出一次 | `2` |
| `pulse_ticks` | 输出亮几拍 | `1` |
| `reset` | 是否提供复位输入（以后） | `false` |

**为什么要参数化**：时序题一旦写死，改一关就要改代码。把这些旋钮放进 JSON，关卡设计时可以直接调，不用碰模拟器。

## C1 的具体做法（MVP 已实现）

1. 每拍先让灯槽输出“本拍已排队”的值（每格 1 拍延迟）。
2. 信号源产生本拍电平。
3. 门是 0 延迟：
   - 无环：按拓扑顺序算一次，避免把“门链传播”误判成毛刺。
   - 有环：迭代最多 16 次；不收敛就标成毛刺/不稳定，不崩溃。
4. 灯槽采样本拍输入，排到下一拍。
5. 目标端口逐拍比对，第一处不一致就记下“第几拍、期望、实际”。

> 诚实说明：MVP 的“毛刺”目前只覆盖“组合环不收敛”。真正的“两条路径延迟不同导致同一拍多次翻转”，要等第三批做逐事件检测时再增强。现在先把 0 延迟门 + 灯槽延迟的地基打稳。

## C5 的确定性衰减（待第二批实现）

建议规则（先写在这里，等做中继时落地）：

- 每个信号有一个“强度”值，默认 3。
- 每经过 1 格灯槽，强度 -1。
- 强度到 0 后，再往后输出强制为低。
- 中继器把强度重置为 3，并继续传递。
- 不用“随机翻转”，因为随机不可读、不可复现、也难做验证。

具体阈值等第二批做关卡时再调；关键是**确定性**，同一布局每次跑结果一样。

## C20 星级与拍数窗口

2026-10-27 起，目标不再要求“在唯一固定拍数精确匹配”，而是允许目标序列整体后移：

- 关卡 JSON 增加 `reference_finish` 与 `star_thresholds: {three, two, one}`。
- 目标序列从 `start_tick` 起，最早结束拍为 `start_tick + expect.size - 1`；
  只要在 `one` 拍前能匹配到完整序列，就算通关。
- 完成拍 = 最早匹配到的那次序列的最后一拍。
- `three` 及以内 = 3 星；`two` 及以内 = 2 星；`one` 及以内 = 1 星；超过 `one` = 失败。
- 3 星阈值贴着参考解；2 星适度放宽；1 星只要在窗口内通关。拿 3 星必须压拍数，不能靠慢速通关。
- 失败仍保留“首错拍、期望、实际”；窗口内第一次候选不匹配只作为反馈，不立即判失败。
- 进度存档记录每关历史最高星级；关卡选择与游戏内关卡按钮显示星级。

## C21 OR / NOT 的输入合并与结算语义（澄清，不改变行为）

- 门的输出在**同一拍内**按拓扑顺序计算，门本身 0 延迟；灯槽采样本拍输入、排到下一拍，因此每格灯槽是 1 拍延迟。
- **OR**：左输入（W）和下方输入（S）是两个输入桶；每个桶内如果有多条上游，按按位 OR 合并；
  输出 = 桶 W OR 桶 S。也就是“任意一路亮就亮”，没有额外阈值。
- **NOT**：只有左输入 W；输出 = 1 - 输入。输入低时输出高，输入高时输出低；0 延迟。
  因此非门在初始（输入低）时输出高；脉冲到达输入的那一拍输出低，下一拍恢复高。
- 同一个输入端口接多条上游时，当前实现按 OR 合并，不报“多驱动”错误；校验只要求端口非空。
  关卡设计避免无意多驱动；若以后要改成“多驱动报错”，需单独决策。
- 有环门网络才迭代到不动点（上限 16）；灯槽会切断同拍环，所以经过灯槽的环表现为逐拍环形振荡，不是同拍组合环。
  当前 5 关没有门级组合环。
