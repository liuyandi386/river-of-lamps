# 元件与模拟规则（MVP）

> 这份文档是“代码之外的规则说明”。如果代码和文档打架，以测试和本文为准，并尽快统一。

## 1. 时间

- 游戏按**拍**（tick）推进，不是连续物理时间。
- 一拍 = 一个离散时间步。
- 暂停不消耗拍。
- 拍数预算 `tick_budget`：从第 0 拍开始，到 `tick_budget - 1` 拍为止。超出即超时。

## 2. 网格与方向

- 网格左上角 `(0,0)`，x 向右，y 向下。
- MVP 固定朝向，不做旋转：
  - **信号源**：输出在 **E**（右）。
  - **灯槽**：由 `flow_dir` 指向下一格。
  - **非门**：输入 **W**（左），输出 **E**。
  - **与门/或门**：输入 **W** 和 **S**（下），输出 **E**。
  - **目标端口**：输入 **W**。

> 以后加旋转时，只改 `ComponentRules` 的端口映射，模拟器不用动。

## 3. 灯槽（wire）

- 每格灯槽延迟 **1 拍**。
- 灯槽是“有方向的灯带”：`flow_dir` 指向下一格。
- 玩家从信号源/门输出开始，按住左键逐格拖；拖到门/目标的输入旁，灯槽方向指向它。
- 灯槽不允许分叉、交叉、覆盖已有灯槽（MVP 简化）。
- 右键删除一整条灯槽路径。
- 灯槽不算功能元件，不占 `max_components`。

## 4. 门（gate）

门是**组合逻辑，0 延迟**：

| 元件 | 输入 | 输出 |
|---|---|---|
| 非门 | W | `1 - W` |
| 与门 | W, S | `W & S` |
| 或门 | W, S | `W | S` |

- **或门不是 XOR**：`0/0 → 0`，`1/0 → 1`，`0/1 → 1`，**`1/1 → 1`**。
  第 5 关要求两路错开 2 拍，是为了得到“亮-灭-亮”的时序，不是因为两路同时高会失效。
- 未连接的输入按低电平（0）处理；但运行前校验会要求所有输入都接上。
- 同一个输入端口接多条上游时，当前实现按按位 OR 合并（不报多驱动错误）；关卡避免无意多驱动。
- 非门在初始输入为低时，第 0 拍输出就是高；输入变高那一拍输出低，下一拍恢复高。
- 无环门网络按拓扑顺序求值一次。
- 有环门网络迭代到不动点（上限 16）；不收敛标记为不稳定/毛刺。灯槽会切断同拍环，所以经过灯槽的环是逐拍振荡，不是同拍组合环。

## 5. 信号源（source）

| 模式 | 行为 |
|---|---|
| `high` | 每拍都输出高 |
| `low` | 每拍都输出低 |
| `pulse` | 只在 `pulse_at_tick` 那一拍输出高，其余低 |

## 6. 目标端口（target）

- 按拍采样输入。
- `expect` 是逐拍期望值数组；`start_tick` 是**最早**允许的开始拍。
- 目标序列可以整体后移：最早结束拍是 `start_tick + expect.size - 1`，
  最晚由关卡的 `star_thresholds.one` 决定；在窗口内最早匹配到完整序列的一次决定完成拍。
- 完成拍 `<= three`：3 星；`<= two`：2 星；`<= one`：1 星；超过 `one`：失败。
- 窗口内第一次候选不匹配只记录 `{tick, expected, got}` 作为反馈，不立即判失败；
  之后仍可能匹配。窗口结束仍无匹配才失败。
- 目标序列必须落在 `tick_budget` 内，并且 `one` 不得超过 `tick_budget - 1`。
- 进度存档记录每关历史最高星级。

## 7. 一拍内的顺序

1. 灯槽输出本拍已排队值（初始为低）。
2. 信号源产生本拍电平。
3. 门求值（0 延迟）。
4. 灯槽采样本拍输入，排到下一拍。
5. 目标端口比对。
6. 记录本拍帧（信号值、翻转、毛刺、错误）。

## 8. 运行前校验

按“运行”时检查：

- 有目标端口；
- 每个目标都有输入；
- 每个门的必需输入都接上；
- 每段灯槽都有上游信号；
- 功能元件数不超过 `max_components`；
- 目标序列在预算内。

任何一条失败，不进入运行，直接显示第一条错误。

## 9. 已知简化（MVP）

- 没有干扰源、屏蔽线、衰减/中继。
- 没有延迟元件、脉冲发生器、边沿触发器、计数器。
- 没有真正的“同拍多次翻转”逐事件检测；只检测组合环不收敛。
- 固定朝向，不能旋转。
- 灯槽不能分叉/交叉。
- 目标端口只支持单目标。

这些都在后续批次里逐步补。
